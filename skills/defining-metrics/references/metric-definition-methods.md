# Metric Definition Methods

Use this reference to choose the semantic dimensions, invariants, and examples that make a reusable metric unambiguous. Do not require irrelevant sections mechanically.

## Definition dimensions

| Dimension | Resolve | Typical failure if omitted |
|---|---|---|
| Purpose and owner | Decision supported, official owner, consumers, allowed interpretation | Same name used for incompatible decisions |
| Unit and grain | Entity, period, output unit, dimensions | Accounts counted as contracts or events |
| Population | Admission moment, inclusions, exclusions, status/effective rules | Survivorship or denominator drift |
| Numerator | Qualifying condition, once-per-entity rules, success state | Repeated events inflate results |
| Denominator | Eligible opportunities, exposure, time, or entities | Numerator and denominator refer to different populations |
| Identity/deduplication | Canonical key, correction order, duplicate/version behavior | One entity contributes several times |
| Source mapping | Profiled fields, joins, precedence, effective mapping | Convenient but non-authoritative source wins |
| Time | Event/effective/receipt time, timezone, boundaries, cutoff | Late data or boundary records enter wrong period |
| Aggregation | Ratio-of-sums, average-of-ratios, weights, hierarchy | Group and total results cannot reconcile |
| Missingness | null, zero, unknown, not applicable, suppressed | Unknown silently becomes zero or disappears |
| Comparison | Baseline, cohort, target, comparability, restatement | Trend reflects population/definition changes |
| Precision | Calculation precision, rounding stage, display | Rounded components produce a different total |
| Governance | confirmation, currentness, change triggers, restatement | Historical reports silently change meaning |

## Invariant patterns

Choose invariants that would fail under a plausible implementation error.

### Membership and identity

- Every numerator entity-period belongs to the denominator population for the same entity-period.
- Each canonical entity contributes at most once where the metric is entity-based.
- Excluded entities cannot re-enter through an event-only join.
- Unknown identity remains unresolved or excluded according to an explicit rule; it never receives a fabricated key.

### Units and arithmetic

- Numerator and denominator use compatible units and periods.
- A count cannot be averaged as if it were a rate; a rate cannot be summed without a defined weighting basis.
- Bounded rates remain within their declared range.
- A zero denominator produces the stated no-result value, not an infinity or an accidental zero.

### Time and corrections

- Period assignment uses the named timestamp and timezone at both boundaries.
- Receipt cutoff controls data availability; it does not replace event/effective time unless explicitly defined.
- A correction replaces or amends the earlier record according to source semantics without double counting.
- Late corrections trigger the named restatement or next-cycle treatment.

### Aggregation and reconciliation

- Disjoint partitions reconcile to the overall numerator and denominator before the ratio is recomputed.
- Weighted metrics use declared weights from the same eligible population.
- Missing dimension values follow the declared `Unknown`, exclusion, or suppression treatment.
- Segment or cohort assignment is effective for the same period as the metric.

### Source mapping

- Every required concept maps to a named profiled source field or documented transformation.
- Precedence is deterministic when two sources disagree.
- Join cardinality matches the intended grain before aggregation.

For each chosen invariant, append “catches: [specific wrong behavior].” If no realistic break can be named, the statement may be explanatory prose rather than a useful invariant.

## Hand-derived example design

Use a table small enough to calculate without code. Give literal records, eligibility, qualifying state, times, and expected intermediate memberships—not only the final percentage.

Include the smallest relevant set:

1. **Ordinary:** demonstrates the main population and formula.
2. **Boundary:** exercises a period edge, cutoff, zero denominator, or rounding rule.
3. **Counterexample:** duplicate/correction, ineligible activity, multiple contracts, unknown segment, or missing value.

Compute expected numerator, denominator, and output independently. State why each row is admitted, excluded, deduplicated, or unresolved. A fixture generated by the candidate query cannot validate that query.

## Change classification

| Change | Definition action |
|---|---|
| New period values under the same population, mappings, and rules | Reuse the current Definition. |
| Same-period correction handled by the current correction/restatement rule | Recompute or restate as specified; do not redefine. |
| Source bytes/format changed but profiled meaning is equivalent | Keep the Definition; update period evidence if needed. |
| Population, formula, unit, grain, time basis, deduplication, weight, or comparison changed | Revise and reconfirm the Definition with the Plan. |
| Source authority, grain, field meaning, or mapping changed | Return to profiling, then revise affected mapping/invariants. |
| Display-only rounding or label changed with raw semantics fixed | Update presentation in the Plan/report; preserve metric meaning. |
| Intended decision or audience changed | Return to framing before deciding metric reuse. |

## Common semantic traps

- Averaging subgroup percentages instead of recomputing from subgroup numerators and denominators.
- Counting events when the unit is entities.
- Defining the denominator from observed numerator activity and losing zero-activity entities.
- Using the latest snapshot for a historical period without effective dating.
- Treating absent, zero, unknown, not applicable, and suppressed as equivalent.
- Mixing event time for some sources with receipt or extraction time for others.
- Applying a corrected source record without its replacement/deduplication rule.
- Changing an allowlist, threshold, mapping, or population without treating it as a semantic change.

Name these only when they are plausible for the specific metric; do not add boilerplate warnings that no consumer will use.
